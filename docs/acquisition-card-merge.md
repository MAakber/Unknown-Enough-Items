# 来源卡片合并 — 1.2.10

获取途径在显示层合并同一对象 ID 的来源记录。原生来源索引保持各预制件与
子对象独立，继续保留其实际概率和条件。

合并必须满足以下字段完全一致：来源种类、对象 ID、破坏或击败动作、概率是否
已知、未舍入的单次概率、抽取次数、耐久范围、容器 ID 与液体默认体积。
只有显示百分比相同、物品名称相同，不能作为合并依据。没有对象 ID、概率不完整
或耐久未知的记录继续按原预制件区分。

例如独立物资箱与 `BigContainer` 中的同类物资箱，若以上规则一致，显示一张
“物资箱”卡片，悬浮说明列出合并的来源记录和其上下文。卡片采用原始路线，
不累加概率、抽取次数或必定掉落数量；抽取一次、0.58%、耐久 100% 的两条
来源合并后仍显示原值。

来源组标识不依赖首次读到的预制件路径、显示名称或界面语言。补齐相同来源
形态时保持组标识和已有组之间的顺序，沿用详情分页锚点。液体继续保留其
容器链，不同容器分别显示。图标可以从同组的已扫描来源取得，不增加资源加载。
每页 1–4 行设置、输入处理和物品列表沿用已有实现。

开始时的 1.2.9 DLL、配置、66 个源码与资料文件、Git 差异保存在
`artifacts/acquisition-merge-2026-11-23/baseline/`。此目录同时保存本任务的
构建、检查与安装证据。不要用整个文件恢复覆盖此前尚未提交的修复。

10 个正式版与 Gale 核心引用哈希核对通过，编译 0 警告、0 错误；实际 API
核对、1,419 项回归断言（含 26 项新增合并检查）、23 项包自动化测试及版本
一致性通过。开始备份中 57 个其余文件字节未变，原生来源索引、扫描、输入、
列表与既有回归断言保留。

## 游戏内核对

- 截图中规则相同的物资箱来源合为一张，悬浮说明仍能看到独立与嵌套来源。
- 不同概率、次数或耐久的同类来源仍分开，显示数字没有累加。
- 液体的容器图标、默认体积、来源查询和悬浮说明正常。
